# スパ人（スパジン）業者共有用 仕様書

作成日：2026年7月23日  
目的：都府県別の温浴施設データを使い、施設ごとの個別コードを増やさずに診断・施設推薦・スパ神キャラクター演出を実装するための共有仕様。

---

## 1. 全体方針

「スパ人」は、ユーザーの今夜したいことをもとにスーパー銭湯・温泉施設を案内する、キャラクター演出つきの温浴コンシェルジュサイトです。

今後、施設数が300件以上になる想定のため、施設ごとに個別のJavaScript分岐コードを書く方式は避けます。

基本方針は以下です。

1. 施設情報は都府県別のスプレッドシート、CSV、JSONで管理する
2. サイト側は共通ロジックで施設データを読み込む
3. 施設選定は `prefecture` / `area_type` / `q1_type` / `q2_type` / `priority` で行う
4. 近場・遠出の質問は廃止する
5. 3つ目の条件は「都府県・エリア選択」とする
6. スパ神キャラクターは施設に固定しない
7. 最後の施設紹介キャラクターは、施設タグをもとに重み付きランダムで選ぶ
8. 紹介文は施設ごとの固定文ではなく、キャラクター別テンプレートに施設情報を差し込む


## 4. q3_type 廃止に伴う列名変更

旧仕様の `q3_type` は近場・遠出判定に見えるため廃止します。

| 旧列名 | 新列名 | 内容 |
|---|---|---|
| q3_type | area_type | エリアコード |
| q3_label | area_label | 表示用エリア名 |
| condition_key | diagnosis_area_key | 診断用キー |

例：

```text
diagnosis_area_key = 千葉:AB:bay
```

意味：

```text
千葉県 / q1_type=A / q2_type=B / area_type=bay
```

## 7. 施設選定ロジック

施設選定は、ユーザー回答から以下条件で施設マスターを絞り込みます。

```js
function findFacilities(facilities, selection) {
  return facilities
    .filter(f => f.prefecture === selection.prefecture)
    .filter(f => f.area_type === selection.area_type)
    .filter(f => f.q1_type === selection.q1_type)
    .filter(f => f.q2_type === selection.q2_type)
    .sort((a, b) => priorityScore(a.priority) - priorityScore(b.priority));
}

function priorityScore(priority) {
  const scores = {
    primary: 1,
    secondary: 2,
    candidate: 3
  };
  return scores[priority] || 99;
}
```

### priority の意味

| priority | 用途 |
|---|---|
| primary | 最初に表示する王道施設 |
| secondary | チェンジ時に表示する代替施設 |
| candidate | 追加候補・ランダム候補 |

## 9. スパ神選定ルール

施設紹介キャラクターは、施設の `facility_tags` をもとに候補化し、重み付きランダムで選びます。

### タグと候補キャラ

| facility_tags に含まれる語 | 候補スパ神 | weight目安 |
|---|---|---:|
| 美肌, 天然温泉, 黒湯, 炭酸水素塩泉, ぬるとろ | 泉潤天 | 80 |
| サウナ, 水風呂, ロウリュ, アウフグース, 熱波 | 熱波大黒 | 80 |
| 岩盤浴, 炭酸泉, おこもり, 漫画, ラウンジ | 御堂福禄 | 75 |
| 露天, 絶景, 海, 山, 展望, 外気浴 | 暮林恵比寿 | 70 |
| 王道, 清潔, バランス, 普段使い | 湯川明神 | 60 |
| 常時フォールバック | 湯川明神 | 30 |

### 実装例

```js
function selectIntroGuardian(facility) {
  const tags = facility.facility_tags || [];
  const candidates = [];

  if (hasAny(tags, ["美肌", "天然温泉", "黒湯", "炭酸水素塩泉", "ぬるとろ"])) {
    candidates.push({ guardian: "izumi", weight: 80 });
  }

  if (hasAny(tags, ["サウナ", "水風呂", "ロウリュ", "アウフグース", "熱波"])) {
    candidates.push({ guardian: "neppa", weight: 80 });
  }

  if (hasAny(tags, ["岩盤浴", "炭酸泉", "おこもり", "漫画", "ラウンジ"])) {
    candidates.push({ guardian: "mido", weight: 75 });
  }

  if (hasAny(tags, ["露天", "絶景", "海", "山", "展望", "外気浴"])) {
    candidates.push({ guardian: "kurebayashi", weight: 70 });
  }

  if (hasAny(tags, ["王道", "清潔", "バランス", "普段使い"])) {
    candidates.push({ guardian: "yukawa", weight: 60 });
  }

  candidates.push({ guardian: "yukawa", weight: 30 });
  return weightedRandom(candidates);
}

function hasAny(tags, keywords) {
  return keywords.some(keyword => tags.includes(keyword));
}
```

## 10. 紹介文テンプレート方式

施設ごとに5人分の固定紹介文は作りません。  
300施設 × 5人 = 1,500文になり、制作・修正コストが大きくなるためです。

紹介文は、キャラクター別テンプレートに施設情報を差し込む方式にします。

### 差し込み変数

| 変数 | 内容 |
|---|---|
| `{facility_name}` | 施設名 |
| `{spring_quality}` | 泉質・風呂特徴 |
| `{effects}` | 主な効能 |
| `{source_point}` | おすすめポイント |
| `{area_label}` | エリア名 |

### 湯川明神テンプレート例

```text
{facility_name}、これはかなり使いやすいです。
{source_point}
変に冒険しすぎず、ちゃんと満足できるタイプですね。
```

### 泉潤天テンプレート例

```text
{facility_name}は、{spring_quality}のお湯が魅力だよぉ。
{effects}をやさしく狙えるから、今日は肌と心をふわっと甘やかしてあげよ〜。
```

### 熱波大黒テンプレート例

```text
{facility_name}、これは切り替えたい夜に強いですッ！
{source_point}
ここで汗を出したら、仕事の熱もまとめて流せます！
```

### 御堂福禄テンプレート例

```text
{facility_name}は、滞在設計で化ける施設ですね。
{source_point}
```

### 暮林恵比寿テンプレート例

```text
{source_point}

```

## 11. 同じ施設でも飽きさせないための演出

同じ施設が選ばれても、毎回同じキャラクター・同じ文章にしないことを重視します。

実装方針：

1. 施設は診断条件で選ぶ
2. 紹介キャラは施設タグから候補化する
3. 候補キャラから重み付きランダムで選ぶ
4. キャラごとに複数テンプレートを持つ
5. テンプレートもランダムに選ぶ

例：

```text
同じ施設：湯の郷 ほのか 蘇我店

1回目：御堂福禄が「岩盤浴・おこもり」視点で紹介
2回目：暮林恵比寿が「東京湾・露天」視点で紹介
3回目：湯川明神が「王道・使いやすさ」視点で紹介
```

## 13. データ受け渡し形式

制作側への受け渡しは、以下のいずれかを推奨します。

### 推奨1：CSV

スプレッドシートからCSVを書き出して使用します。  
非エンジニアでも管理しやすいため、運用しやすい形式です。

### 推奨2：JSON

Web実装側でそのまま扱いやすい形式です。  
制作会社側でCSVからJSONへ変換しても問題ありません。

### JSON例

```json
{
  "facility_id": "chiba_001",
  "prefecture": "千葉",
  "area_type": "bay",
  "area_label": "【潮風の湾岸】（ベイエリア）",
  "facility_name": "湯の郷 ほのか 蘇我店",
  "spring_quality": "ナノ水各種風呂、人工温泉、炭酸泉",
  "effects": "血行促進、冷え性改善、美肌効果、疲労回復、リラックス",
  "source_point": "東京湾を一望できる展望露天風呂と、広い岩盤浴ラウンジが魅力。",
  "q1_type": "A",
  "q2_type": "B",
  "diagnosis_area_key": "千葉:AB:bay",
  "priority": "primary",
  "facility_tags": ["炭酸泉", "岩盤浴", "露天", "おこもり", "王道"]
}
```

## 14. 業者様への実装依頼文

以下の方針で実装をお願いします。

```text
施設ごとに個別コードを書くのではなく、都府県別の施設マスターCSVまたはJSONを読み込むデータ駆動型で実装してください。

施設選定は、prefecture / area_type / q1_type / q2_type / priority を使って行います。

近場・遠出の q3_type 判定は廃止し、3つ目の選択は都府県とエリア選択に変更します。

スパ神キャラクターは施設に固定せず、選ばれた施設の facility_tags をもとに候補を作り、重み付きランダムで最後の紹介キャラを選定してください。

紹介文は施設ごとの固定文ではなく、キャラクター別テンプレート文に facility_name / spring_quality / effects / source_point / area_label を差し込む方式にしてください。

同じ施設でも、診断のたびに紹介キャラや紹介文パターンが変わるようにしてください。
```

## 15. 重要な注意点

- 施設ごとの個別 `if` 文や個別コンポーネント実装は避ける
- `q3_type` は使用しない
- 施設とスパ神を固定紐づけしない
- 施設データは後から追加しやすい構造にする
- キャラクターの面白さは、施設選定ではなく最後の紹介演出で出す
- 300施設以上に増えても、基本的にコード修正ではなくデータ追加で対応できる設計にする
